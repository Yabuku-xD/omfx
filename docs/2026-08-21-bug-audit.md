# omfx end-to-end bug audit

**Date:** 2026-08-21
**Scope:** all of `src/` (28.0k lines), plus the claims in `docs/research/`.
**Method:** `zig-0.16`, `zig-tiger-style`, `zig-code-review`, `zig-testing`,
`zig-debugging` skills; `/diagnosing-bugs`; `/thermo-nuclear-code-quality-review`.
**Baseline at audit time:** 503 unit tests, 5/5 live e2e (`scripts/e2e.sh`).

Every FIXED entry below was reproduced first, then fixed, then pinned by a named
regression test. Every OPEN entry has an exact solution and the reason it was
not applied unilaterally.

## Severity 1 — shipped, exploitable, fixed

### S1-1 Permission bypass: checks read the escaped command, the shell ran the decoded one

**Where:** `src/core/permissions.zig`, `src/core/hooks.zig`

Tool arguments arrive as JSON *string values*, so the raw text still holds `\t`
and `\n` as two characters each. The permission layer judged that form; dispatch
decoded it before running. Reproduced:

```
command: ls\t&&\trm\t-rf /tmp/victim
  raw     isReversibleBash = true    <- auto-approved; allowed in read-only plan mode
  decoded isReversibleBash = false
```

The deny list looks for a real tab (`"rm\t"`); the escaped form carries a
literal backslash-t, so it missed, and the allow-prefix then matched the leading
`ls`. A destructive command read as reversible.

**Fix (applied):** `sse.unescapeInto(buf, s) ?[]const u8` — an allocation-free
decode, because these checks run before any allocator is in scope.
`blockedByPlan`, `isRoutine`, and the DSL matcher decode first;
`permissions.max_command = 8192` bounds it and a command too long to decode
returns null, which every caller treats as **unsafe** (`.deny` / blocked), never
as "probably fine". `hooks.pre` uses the same helper so AGENTS.md `never:` rules
match what will actually run.

**Test:** `permissions.zig` — "a permission check judges the decoded command,
not the escaped one" (asserts the escaped form *would* have passed, so the
regression is visible), and "an undecodable command fails closed".

### S1-2 A persisted `yolo` disarmed every headless run

**Where:** `src/main.zig`

`~/.omfx/settings.json` remembers `last_mode`. `omfx ask` inherited it, so a
`/yolo` chosen once in an interactive session silently removed the permission
gate from every later non-interactive invocation — CI, pipes, scripts.
Reproduced:

```
$ omfx ask "run bash with command: rm -rf victim.txt"   # no --yolo, no tty
victim present: False
```

**Fix (applied):** persisted mode applies only when
`parsed.command == .interactive`. One-shot elevates on an explicit `--yolo` /
`--auto` / env var and nothing else. Verified: `permission denied`, file
survives; `--yolo` still works.

**Test:** `permissions.zig` — "one-shot mode without a tty refuses a destructive
command".

## Severity 2 — wrong behavior, fixed

### S2-1 Compaction made an oversized short thread *larger*

**Where:** `src/core/compact.zig`, `planKeepOriginalEx`

The `from < 2` floor was checked **before** the parity adjustment, so
`from -= 1` could land on 1. `stitch` then dropped `turns[1..1]` — nothing —
while still inserting the placeholder and an empty summary. Reproduced:

```
plan(count=4, chars=60002) = .{ .drop = 1 }
in=4 turns    -> out=6 turns
in=60002 chars-> out=60144 chars
```

This is precisely the case `char_budget` exists for (a few huge tool results).
The loop compacts, the thread grows, and the next turn compacts again — a slow
climb toward the context limit with no relief.

**Fix (applied):** re-check the floor *after* the parity step, and clamp **up**
to the first valid odd point rather than giving up, because the char budget is
asking for a drop:

```zig
if (from % 2 == 0) from -= 1;
if (from < 2) {
    if (3 >= count) return .keep;
    from = 3;
}
```

Clamping up (not returning `.keep`) preserves the existing contract that a
short-but-oversized thread must still compact.

**Tests:** "compaction never returns a longer thread than it was given", and a
sweep over `count` 0..64 × four char budgets asserting every `.drop` names a
point with `from >= 2`, `from < count`, and odd parity.

### S2-2 Five spawns could hang the agent forever

**Where:** `src/tools/mcp.zig`, `src/core/diagram.zig`, `src/core/context.zig`,
`src/tools/isolate.zig` (×2)

`Child.wait` blocks until the command returns, and the interrupt key cannot
rescue it (`pollCancel` fires at tool boundaries and SSE lines; a blocking wait
is neither). MCP was the worst: an arbitrary user-configured server that starts
but never answers blocks `readJson` on `takeDelimiterExclusive` indefinitely.

**Fix (applied):** `deadline.capped(argv)` at each site — MCP 30s, `mmdc` 30s,
`git status` 15s, `git worktree add` 60s. Verified stdin survives the watchdog
first, since MCP needs it.

## Severity 3 — correctness / hygiene, fixed

### S3-1 `jsonAtom` cannot parse bare booleans

**Where:** `src/tools/dispatch.zig`

It understands quoted strings and numbers only, so a bare `false` returned null.
`{"background": false}` fell through to the default and detached a command the
model was waiting on. **Fix:** `Args.flag` scans for the literal itself and
accepts `true` / `"true"` / `1` / `false` / `"false"` / `0`.

### S3-2 `zig fmt` was not clean

Five files under `src/tools/` were unformatted, against the explicit AGENTS.md
rule. **Fix:** `zig fmt src/` applied; tests still green.

## OPEN — exact solutions, not applied

These change behavior or public claims. Each is a decision, not an oversight.

### O-1 `never:` rules are substring-only, so whitespace evades them

**Where:** `src/core/contract.zig`, `blocksBash`

```zig
.never => |n| if (std.mem.indexOf(u8, command, n) != null) return true,
```

A rule `rm -rf` does not match `rm<TAB>-rf` or `rm  -rf`. Decoding (S1-1) fixed
*which bytes* are matched; it cannot fix the matcher.

**Exact solution:** normalize both sides before comparing — collapse runs of
whitespace to one space and trim:

```zig
fn normalizeWs(buf: []u8, s: []const u8) ?[]const u8 {
    var n: usize = 0;
    var prev_space = true; // leading run is dropped
    for (s) |c| {
        const is_space = c == ' ' or c == '\t' or c == '\n' or c == '\r';
        if (is_space) {
            if (prev_space) continue;
            if (n == buf.len) return null;
            buf[n] = ' ';
            n += 1;
            prev_space = true;
        } else {
            if (n == buf.len) return null;
            buf[n] = c;
            n += 1;
            prev_space = false;
        }
    }
    return std.mem.trimEnd(u8, buf[0..n], " ");
}
```

Apply to the rule text at parse time and to the command in `blocksBash`.

**Why not applied:** this widens what every existing AGENTS.md `never:` rule
blocks. That is almost certainly desirable for a *deny* rule, but it is a
semantic change to a user-facing contract and belongs to the project owner.

### O-2 SSVP computes CDS over bag-of-words, not embeddings

**Where:** `src/core/ssvp.zig`

Rodrigues (arXiv:2606.21666) specifies CDS over **embeddings of a 3-sentence
summary**. The implementation is cosine over token count vectors:

```zig
/// CDS = 1 - cosine(bag(a), bag(b)).
```

τ = 0.25 is correctly sourced from the paper's FP calibration (1.1% at 0.25,
5.6% at 0.22). The code comment is honest about the substitution. But the
failure modes differ from the paper's: lexical cosine catches "Barcelona vs
Lisbon" (different tokens — which is the paper's own example, and the only case
the test covers) while missing drift where wording matches and meaning diverged,
and false-positiving where meaning matches and wording did not.

**Exact solution, cheapest first:**
1. Rename to `lexical_cds` / `LexicalDivergence` and state in the module doc
   that this is a lexical proxy, so nothing downstream reads it as the paper's
   metric. Zero risk, removes the overclaim.
2. Add a shingle/Jaccard term over 3-grams alongside the unigram bag — catches
   reordering that unigrams miss, still allocation-free.
3. Only if peers become load-bearing: an embedding call behind
   `settings.ssvp = embed`, defaulting off, since it costs a round trip per
   sync check.

**Why not applied:** (1) is a naming change to a paper-referenced module and
(3) changes the cost model of every peer turn.

### O-3 Two research docs say "Not implemented" for code that ships

**Where:** `docs/research/2026-08-20-peer-lag-ssvp.md`,
`docs/research/2026-08-20-self-improving-harness.md`

Both carry `**Status:** research only. Not implemented.` while `ssvp.zig` and

### O-4 The playbook has never written a line, for two independent reasons

**Where:** `src/core/agent.zig` `recordVerify`, `src/tools/diag.zig`
`detectVerifier`

`.omfx/playbook.jsonl` is never created, in this repo or a scratch one. Two
gates, both real:

1. `.clean` only records **board notes**, so a solo session (no peers) writes
   nothing however green the verify.
2. `verify` itself was inert for most repos — `detectVerifier` knew Zig and npm
   only. **Now fixed:** the table covers Cargo, Go, tsconfig, pyproject,
   setup.py, Gemfile, pom.xml, and the JS lockfiles.

Gate 1 remains. The self-improving-harness doc's own design says
*"if verify passed and pattern seen >= 2 times: Curator adds/merges a skill"* —
it does not require a board.

**Exact solution:** in `recordVerify`'s `.clean` arm, when
`board.parseAll` yields zero notes, fall back to the trace:

```zig
.clean => {
    const tail = board.loadTail(allocator, io, workspace);
    defer if (tail.len > 0) allocator.free(tail);
    var notes: [board.max_notes]board.Note = undefined;
    const n = board.parseAll(tail, &notes);
    if (n == 0) {
        // Solo session: the verified tool is the pattern worth remembering.
        if (trace) |t| {
            if (t.last_tool.len > 0) {
                var buf: [playbook.text_max]u8 = undefined;
                const line = std.fmt.bufPrint(&buf, "verified {s}", .{t.last_tool}) catch t.last_tool;
                playbook.noteVerified(allocator, io, workspace, line);
            }
        }
        return;
    }
    // ... existing per-note path
}
```

**Why not applied:** this starts writing a new file into every user's workspace
on every clean verify. That is a product decision about disk and privacy.

### O-6 Seven tests write to fixed `/tmp` paths

**Where:** `memory.zig`, `relay.zig`, `playbook.zig` (×2), `skills.zig` (×2),
`cmds.zig`

e.g. `/tmp/omfx-skills-list-ws`. Two concurrent suite runs collide, and they
leave litter. Each does `deleteTree` first so they are self-healing in
sequence — this is latent, not currently failing.

**Exact solution:** use `std.testing.tmpDir(.{})` and derive the workspace as
the other tests already do:

```zig
var tmp = std.testing.tmpDir(.{});
defer tmp.cleanup();
const ws = try std.fs.path.join(a, &.{ ".zig-cache", "tmp", &tmp.sub_path });
defer a.free(ws);
```

Also `skills.zig:130` uses `catch unreachable` on `createDirPath`; make it
`try` — a filesystem call can fail and `unreachable` is UB in ReleaseFast.

### O-7 Tiger-style: 100-column limit violated in 8 files

`catalog.zig` 67 lines, `web_search.zig` 61, `client.zig` 61, `cmds.zig` 61,
`agent.zig` 39, `oauth.zig` 34, `dispatch.zig` 29, `menus.zig` 24.

**Exact solution:** most are single-line struct literals in the tool/provider
tables. Add a trailing comma inside each literal and let `zig fmt` wrap them.
Mechanical, but it touches the two files most likely to be edited next, so do it
on its own commit.

### O-8 `bash.budget` is mutable global state

**Where:** `src/tools/bash.zig`

The per-call timeout is threaded through a file-level `var budget` rather than
four signatures. Safe today — every entry point sets it immediately before the
spawn reads it, and the whole path is synchronous and single-turn. It is a
latent hazard if a peer ever runs a nested turn concurrently.

**Exact solution:** add `secs: u32` to `runPolicy`, `spawnConfined`, and
`spawnShell`, and delete the global. Four signatures, no behavior change.

## Verified sound (checked, no defect)

- **Slash surface** — 46 declared, 46 enum tags, all dispatched. `/continue` and
  `/resume` are handled as `@"continue"` / `@"resume"`.
- **Zig 0.16 APIs** — no `@Type`, `std.io.fixedBufferStream`, `Thread.Pool`,
  `std.crypto.random`, or `std.meta.intToEnum`. One
  `std.fmt.bufPrintZ` (`ext/host.zig:101`) which is deprecated-but-present; low
  priority.
- **Truncating casts** — `wsWriteText` guards `payload.len <= 65535` before the
  shift and returns `error.FrameTooBig` past it. `timeout` clamps to 100_000
  before `@intCast` to u32.
- **`catch unreachable` in `trim.zig`** — both are provably in range (a usize
  plus 5 chars in 32 bytes; three usizes plus text in 128).
- **`bufPrint ... catch "fallback"` in `main.zig`** — every fallback is
  degraded-but-honest ("unknown command" instead of naming it), never a claim of
  success.
- **Memory** — the test allocator reports no leaks across 503 tests.
